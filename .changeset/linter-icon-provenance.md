Icons are now verified against the published Edelweiss Iconography library instead of being trusted by name. The `esds/icon/…` exemption (its own `Collection 1` tokens) applies only to instances whose main component is remote (`ComponentNode.remote` — published from the team library), so instances of in-file duplicates lose it and their unpublished bindings surface as unknown-collection warnings. A new `Icon local import` rule (warning) flags icon-carrier shapes (vectors from local SVG imports) and instances that are not verified kit instances, through three combined signals: an exact inventory-name match (bare or `esds/icon/` prefix, insensitive to the trailing spaces some kit component-set names carry), Figma's own asset heuristic (`isAsset`), and the canonical kit icon sizes (16/20/24/32/40) — so generically named local imports (`Vector path`) and instances of local icon components (`Icon`, reported as «From this file» by Figma) are caught too. Nodes whose subtree carries an image fill stay silent (the asset heuristic fires for raster images as well); drawn containers remain with `icon-as-frame` and local components with `local-duplicate`.
