## Token Architecture

Our token system follows the Design Tokens Community Group (DTCG) standard with a three-tier architecture:

- <a href="./?path=/docs/design-tokens-t1--docs">T1 Primitive tokens</a> for foundational tokens
  values
- <a href="./?path=/docs/design-tokens-t2--docs">T2 Semantic tokens</a> for semantic abstraction
  tokens
- <a href="./?path=/docs/design-tokens-t3--docs">T3 Component tokens</a> for component-specific
  tokens

#### Using `*.root.css` files

Root CSS files could be loaded using query, for example:

```html
<link
  rel="stylesheet"
  href="@infomaniak-design-system/tokens/css/tokens.root.css"
/>
<link
  rel="stylesheet"
  href="@infomaniak-design-system/tokens/css/modifiers/product/mail.root.css"
/>

<!-- Auto-switch based on system preference -->
<link
  rel="stylesheet"
  href="@infomaniak-design-system/tokens/css/modifiers/theme/light.root.css"
  media="(prefers-color-scheme: light)"
/>
<link
  rel="stylesheet"
  href="@infomaniak-design-system/tokens/css/modifiers/theme/dark.root.css"
  media="(prefers-color-scheme: dark)"
/>
```

#### Using `*.attr.css` files

Attr CSS file could be imported via CSS and activated using data attributes:

**NOTE**: `*.attr.css` CSS files are **optional** and should be imported only if necessary.

```css
@import '@infomaniak-design-system/tokens/css/tokens.attr.css';
@import '@infomaniak-design-system/tokens/css/modifiers/product/mail.attr.css';
@import '@infomaniak-design-system/tokens/css/modifiers/theme/dark.attr.css';
```

Modifiers can also be set on container elements:

```html
<body
  data-esds-theme="dark"
  data-esds-product="mail"
>
  <!-- Dark theme and product mail applies to children -->
</body>
```

```css
@import 'tailwindcss';
@import '@infomaniak-design-system/tokens/css/tokens.root.css';
@import '@infomaniak-design-system/tokens/tailwind.css';
```

## How It Works

### Token Resolution Chain

Token values reference each other in a hierarchy, ensuring consistency across the system:

```
T3-Component  →  button.background.error
                    ↓
T2-Semantic   →  color.background.error.default
                    ↓
T1-Primitive  →  color.red.600 (#E21C40)
```

When a primitive value changes, every token referencing it updates automatically.

### Modifiers Override by Path Matching

Modifiers let you swap the values of existing tokens without changing their names. They work by matching the path of a T2 (semantic) or T3 (component) token and replacing its value for specific contexts.

**How it works:**

1. A modifier file contains the same token path as the base token
2. When applied, it replaces that path's value in the CSS cascade
3. Resolution continues with the new value

**Example**: The `euria` product modifier

The `euria.tokens.json` modifier overrides `color.background.brand.default` by including the same path with a different value:

Base `t2-semantic/color.tokens.json`:

```json
{
  "color": {
    "background": {
      "brand": {
        "default": { "$value": "{color.sky.700}" }
      }
    }
  }
}
```

`modifiers/product/euria.tokens.json`:

```json
{
  "color": {
    "background": {
      "brand": {
        "default": { "$value": "{color.ocean.700}" }
      }
    }
  }
}
```

**Resolution with modifiers:**

Multiple modifiers can be applied simultaneously. In the example below, the `euria` modifier changes the base brand color, then `dark` further adjusts it for the dark theme:

```
With data-esds-product="euria" data-esds-theme="dark":

              T3: button.background.brand.default
                      ↓
              T2: color.background.brand.default
                      ↓
  Euria modifier: color.background.brand.default (color.ocean.700)
                      ↓
   Dark modifier: color.background.brand.default (color.ocean.400)
                      ↓
              T1: color.ocean.400
```

**Apply modifiers using data attributes:**

```html
<body
  data-esds-product="euria"
  data-esds-theme="dark"
>
  <!-- All children resolve with both modifiers applied -->
  <button style="background: var(--esds-color-background-brand-default)">
    Gets a color.ocean.400 background
  </button>
</body>
```

# T1 Primitive Tokens

## What are T1 Tokens?

T1 tokens are the foundational design tokens that define the raw values of your design system. These are the base values that don't reference other tokens.

### Characteristics:

- **Base values**: Colors, spacing, shadows, etc.
- **No references**: They contain actual values (hex colors, pixel dimensions)
- **Platform agnostic**: Represent the design intent without assumptions about usage
- **Source of truth**: Other tiers reference these values

# T2 Semantic Tokens

## What are T2 Tokens?

T2 tokens are semantic design tokens that reference T1 (primitive) values. They define aliases and common names to abstract the T1 tokens.

### Characteristics:

- **Purpose-driven naming**: Named by what they do, not what they are
- **Resolve to T1 values**: Point to primitive tokens for actual values
- **Modifiers**: Modifiers could override T2 tokens to adapt to a specific use cases
- **Cross-component usage**: Used by multiple components
- **Design patterns**: Semantic layer ensures consistent usage

### Examples:

- `color.background.primary` instead of `color.blue.500`
- `spacing.section.large` instead of `spacing.32`

T3 tokens are component-specific design tokens that reference T1 (primitive) and T2 (semantic) values. They define visual properties for specific components.

- `card.padding` using `spacing.section.medium`

# Web

## EsdsIconComponent

### Installation

```shell
yarn add @infomaniak-design-system/esds-icon
```

### Initialization

The icon component needs to be initialized before it can be rendered:

```ts
import { EsdsIconComponent } from '@infomaniak-design-system/esds-icon';

EsdsIconComponent.init();
```

This allows defining the API proxy to fetch the icons and registering the custom element.

You should put it in your `main.ts` or `app.ts` file.

### Usage

```html
<esds-icon
  style="font-size: var(--esds-icon-size-md); color: var(--esds-color-text-primary)"
  name="esds:home"
></esds-icon>
```

#### Styling

The icon may be styled using the following CSS properties:

- `color`: to set the icon's color
- `font-size`: to set the icon's size
